# Add Cinematic Scroll-Driven Animation to Existing Portfolio

I have a fully built portfolio. Do NOT rebuild, redesign, or change existing content, layout, components, routes, backend logic, admin dashboard, auth, or API calls. Your only job: layer a cinematic scroll-driven animation system on top of what exists.

---

## Step 0 — Inspect first

Before writing code:
* List existing sections in order (Hero, About, Skills, Projects, Experience, Contact, etc.)
* Check what's already installed: GSAP/ScrollTrigger, Framer Motion, Lenis, Three.js, or none
* Use whatever is already installed. Only add a new library if nothing suitable exists (prefer Framer Motion's useScroll/useTransform for a Next.js/React app, or GSAP ScrollTrigger if that's already present). Never install two animation libraries.
* Report the plan (which sections, which technique per section) before implementing.

---

## Core concept

Replace independent per-section fade-ins with one continuous scroll timeline: scroll position drives a single animation progress value that the whole page reads from, so background, a persistent visual element, and section content all evolve together instead of "section appears, stops, next section appears."

Three ingredients, working together, not three separate systems:

1. Background transformation: background color/gradient/tone interpolates smoothly across scroll progress (smooth color/tone shift, not literal illustrated scenes): dark neutral at Hero, cooler blue-purple at About, technical/network-tinted at Skills, deepest tone with stronger accent glow at Projects, calm dark-blue at Contact.
2. One persistent element that travels and morphs: a single glowing node/orb/geometric marker that stays on screen (or reappears in the same visual language) through the whole page: represents "you" in Hero, drifts toward content in About, becomes the center of a small skill network in Skills (lines connecting to 4-6 tech nodes, e.g. Java/Python/PostgreSQL/Docker), becomes a connector between project cards in Projects, becomes a "connection endpoint" in Contact.
3. Scroll-linked motion on existing content: existing hero text/image, about text, skill items, project cards, and contact content get scroll-tied transforms (translate/scale/opacity, subtle rotation-to-straighten on entry) instead of a generic on-mount fade.

Implementation note: build the scroll-progress tracking and the persistent node as one shared, reusable piece (a hook + one component), not duplicated per section. Each section just reads progress and renders its own local variant.

---

## Motion rules

Use: transform (translate/scale/rotate), opacity, and color/gradient interpolation, tied to scroll progress via scroll-linked APIs (not scroll event handlers doing manual math). GPU-friendly properties only.

Avoid: particle systems, constant floating/bobbing on elements, heavy blur, large scale jumps, bounce/elastic easing, animating every element independently. Easing should be smooth (ease-out or a custom cubic-bezier), not linear or bouncy.

Feel: smooth, cinematic, professional, like a camera moving through one environment, not a flashy game UI.

Horizontal movement inside Projects (if used) is desktop-only. On mobile, projects still stack vertically with the same reveal/settle animation, no horizontal scroll.

---

## Mobile & accessibility

* Mobile: same section transitions, but reduced parallax distance and reduced motion intensity (simpler transforms, no 3D depth effects). Never disable core scrolling or hide content behind animation.
* Respect prefers-reduced-motion: reduce. Disable the cinematic/parallax/morphing layer entirely, fall back to simple opacity fades, keep all content immediately visible and scrollable.
* Target 60fps. Clean up all scroll listeners/animation frames on unmount. Verify no unnecessary re-renders are introduced.

---

## Non-negotiables

* Preserve existing visual identity, copy, project data, and all working functionality (nav, routing, forms, admin, auth, API calls, links).
* Don't touch backend/database logic.
* Ship working code: no TODO placeholders on core sections, no build errors.

---

## Process

1. Inspect and report plan (sections, chosen library, per-section technique)
2. Build the shared scroll-progress hook and persistent node component
3. Wire background interpolation
4. Apply scroll-linked motion to each existing section in order (Hero, About, Skills, Projects, Contact)
5. Tune timing and easing across the full scroll length
6. Add mobile-reduced variant and prefers-reduced-motion handling
7. Test: full scroll top-to-bottom, all existing functionality, mobile, reduced-motion, production build

Goal: the portfolio should feel like one continuous digital journey the user's scroll is directing, while every existing feature still works exactly as before.
